# خطة حل مشكلة النشر على Render وتجهيز التصدير الثابت (Static Export) مع تعطيل التحليلات الداخلية

## 1. تحليل أسباب المشكلة على Render
- **سبب خطأ `Publish directory build does not exist!`**:
  - عند إنشاء الموقع على Render كـ **Static Site**، تكون القيمة الافتراضية لحقل مجلد النشر هي `build`.
  - تطبيق Next.js ينشئ افتراضياً مجلد `.next`، وعند تفعيل خيار التصدير الثابت ينشئ مجلد `out`، ولا ينشئ مجلداً باسم `build` مطلقاً.
  - محاولة Render العثور على مجلد `build` بعد انتهاء البناء أدت إلى فشل النشر مباشرة رغم نجاح توليد الصفحات.

---

## 2. مراحل التنفيذ

### المرحلة الأولى: إيقاف نظام التحليلات الداخلي والاعتماد على أدوات Google فقط
1. **تعطيل محركات التتبع الداخلي (Internal Analytics Tracker)**:
   - إيقاف إرسال الأحداث التلقائية للزوار والتحويلات إلى `/api/analytics/*` في `hooks/useAnalytics.ts` و `lib/analytics-system.ts`.
   - تعطيل تتبع قواعد البيانات المحلية و Firebase Analytics الداخلية لمنع أي استهلاك لموارد المتصفح أو الخادم.
2. **الحفاظ على أدوات Google الأساسية**:
   - الإبقاء على كود ربط **Google Analytics (GA4)** القياسي في `pages/_app.tsx` للعمل فقط عند توفر `NEXT_PUBLIC_GA_MEASUREMENT_ID`.
   - الحفاظ على تكاملات **Google Search Console** وتوليد خريطة الموقع `sitemap.xml` وملف `robots.txt` وروابط `canonical` والـ Schema لضمان بقاء الأرشفة ومحركات البحث بأعلى كفاءة.
3. **تبسيط واجهة الموقع وإلغاء شاشات الإحصائيات غير الضرورية**:
   - إيقاف لوحة التحكم الداخلية `/admin/analytics` أو تحويلها إلى وضع الخمول لعدم الحاجة إليها طالما الاعتماد كامل على Search Console.

---

### المرحلة الثانية: إعداد التصدير الثابت (Static Export) إلى مجلد `out`
1. **تحديث إعدادات Next.js (`next.config.js`)**:
   - ضبط `output: 'export'` لإنتاج مجلد `out` الجاهز لمواقع Static Site على Render.
   - ضبط `images: { unoptimized: true }` لأن التصدير الثابت في Next.js يتطلب تعطيل محول الصور المعتمد على خادم Node.js.
   - معالجة تعارض `i18n` مع `output: 'export'`: نظراً لأن Next.js يمنع استخدام كائن `i18n` المدمج مع التصدير الثابت، سيتم تهيئة التوليد الثابت للغتين (العربية والإنجليزية) بمرونة عبر المسارات أو المكونات.
2. **تجهيز نماذج الاتصال والطلبات للعمل بدون API Routes**:
   - في بيئة الـ Static Site لا تعمل الـ API Routes المحلية (`/api/contact`, `/api/wholesale-inquiry`).
   - ربط نماذج التواصل والطلب بالبريد الإلكتروني المباشر عبر مكتبة `@emailjs/browser` (الموجودة بالفعل بالمشروع) مع توفير زر التحويل المباشر إلى WhatsApp لضمان عدم فقدان أي استفسار تجاري.

---

### المرحلة الثالثة: إعدادات منصة Render وتجربة البناء
1. **توثيق إعدادات Render للمستخدم**:
   - **Build Command**: `npm install && npm run build`
   - **Publish Directory**: `out`
2. **التحقق البرمجي والتجميع**:
   - تشغيل أمر البناء والتصدير محلياً للتحقق من تكوين مجلد `out` بكافة صفحات الموقع الفرعونية (الرئيسية، المنتجات، المدونة، المجموعات).
   - إجراء فحص `lint_applet` و `compile_applet` للتأكد من خلو المشروع تماماً من أي تعارضات أو أخطاء.
