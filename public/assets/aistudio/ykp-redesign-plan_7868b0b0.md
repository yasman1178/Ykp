# خطة إعادة تصميم موقع YKP Supplies وتحسين تجربة المستخدم والـ SEO

- **الموقع:** https://www.ykp-eg.com
- **المستودع:** https://github.com/yasman1178/Ykp
- **التقنية الحالية:** Next.js (Pages Router) + Tailwind + TypeScript + Firebase + Vercel + نموذج اتصال عبر Gmail SMTP
- **نوع النشاط:** تصنيع وبيع جملة (B2B) لمخدات سفر بتصميمات فرعونية، مع تصدير عالمي

> ملاحظة: التحليل الأولي مبني على الصفحة الرئيسية وواجهة المستودع فقط. المرحلة 0 مطلوبة قبل أي تعديل لتأكيد النقاط التالية على الكود الفعلي.

## 1) الوضع الحالي: أهم الملاحظات

| المحور | الملاحظة |
|---|---|
| الهوية | العنوان "Pharaonic Pillows" والبراند "YKP Supplies"، والمستودع منشور على `ykp.vercel.app` والـ canonical على `www.ykp-eg.com` |
| الثقة | ثلاث شارات ("Certified Quality" / "Egyptian Made" / "Memory Foam Certified") بنفس صورة اللوجو، وأرقام (50+ دولة، 10K+ مسافر) بدون إثبات |
| الروابط | روابط في الفوتر (`/distributor`, `/quality`, `/certifications`, `/partnership`) تحتاج فحص هل هي صفحات حقيقية؛ وروابط المنتجات كلها تذهب لـ `/products` العامة |
| المنتجات | أسماء كولكشن بأكواد غير واضحة للعميل (B123 / T / TB) |
| SEO | الاعتماد على `meta-keywords` (غير مؤثر)، لا يوجد Schema ظاهر، لا نسخة عربية، `og:locale` إنجليزي فقط، حقوق نشر 2025 |
| الأداء | صورة hero بعرض 3840px، رموز هيروغليفية/إيموجي كثيرة في العناوين |
| المستودع | ملفات `*_FIX.md` و`*_SUMMARY.md` كثيرة في الجذر، وملف إعداد Firebase نصي، ويجب التأكد من عدم وجود أسرار في الكود أو التاريخ |

## 2) الأهداف

1. زيادة **طلبات عروض الأسعار (Wholesale Inquiries)** من المستوردين والموزعين.
2. ظهور أفضل في نتائج البحث لكلمات مثل: `wholesale travel pillows`, `memory foam travel pillow manufacturer`, `Egyptian travel pillow supplier`، وما يقابلها بالعربي.
3. موقع سريع وسهل على الموبايل (Core Web Vitals باللون الأخضر).
4. هوية موثوقة: كل ادعاء عليه دليل (شهادات، صور مصنع، أرقام حقيقية).

**مؤشرات النجاح (KPIs):** عدد طلبات الجملة شهرياً، نسبة التحويل من الزيارة للطلب، Lighthouse (الموبايل) ≥ 90 في الأداء/SEO/Accessibility، الصفحات المفهرسة في Search Console، متوسط الترتيب للكلمات المستهدفة.

## 3) مراحل التنفيذ

### المرحلة 0: التدقيق (قبل أي تعديل)
- [ ] تشغيل المشروع محلياً، قراءة `package.json` وإصدار Next.js والاعتماديات القديمة.
- [ ] جرد كل الصفحات والـ API routes والمكونات في `pages/` و`components/`.
- [ ] Lighthouse + PageSpeed Insights (موبايل وديسكتوب) لـ: الرئيسية، المنتجات، منتج، مقالة، اتصال.
- [ ] فحص الروابط المكسورة والـ redirects والـ canonical.
- [ ] فحص الأمان: بحث عن أسرار في الكود وتاريخ git، مراجعة `.env.local.example`، مراجعة قواعد Firebase.
- [ ] تقرير تدقيق `docs/audit.md` بالمشاكل مرتبة حسب (التأثير × الجهد).
- [ ] قياس خط الأساس (Baseline) لكل KPI.

### المرحلة 1: أساسيات SEO التقنية (أعلى عائد، أقل مخاطرة)
- [ ] **دومين واحد:** تثبيت `www.ykp-eg.com` كأساسي، وredirect 301 لباقي الدومينات (`ykp-eg.com`, `ykp.vercel.app`).
- [ ] `sitemap.xml` و`robots.txt` ديناميكيين (تتضمن المنتجات والمقالات).
- [ ] مكوّن `SEO` موحد: title/description فريدة لكل صفحة، canonical، Open Graph، Twitter Card، صورة OG مخصصة لكل صفحة.
- [ ] حذف الاعتماد على `meta-keywords`، والتركيز على المحتوى والعناوين (H1 واحد لكل صفحة، ترتيب H2/H3 منطقي).
- [ ] **Structured Data (JSON-LD):** `Organization`، `WebSite`، `Product` (بدون تقييمات وهمية)، `BreadcrumbList`، `Article`، `FAQPage`، `ContactPoint`.
- [ ] روابط داخلية: Breadcrumbs، منتجات ذات صلة، روابط من المقالات للمنتجات.
- [ ] صفحة 404 مفيدة، وإصلاح أي روابط مكسورة.
- [ ] **الأداء:** تصغير صورة الـ hero وتحويلها لـ WebP/AVIF بأحجام مناسبة، `next/font`، `priority` للصورة الأولى فقط، lazy-load لباقي الصور، `width/height` لمنع CLS، تقليل JS غير الضروري.
- [ ] تسجيل الموقع في Google Search Console وBing Webmaster وإرسال الـ sitemap.

### المرحلة 2: إعادة التصميم وتحسين UX

**الصفحة الرئيسية** (ترتيب مقترح):
1. Hero: وعد واحد واضح + زر "اطلب عرض سعر" كإجراء رئيسي و"تصفح المنتجات" كثانوي.
2. شريط ثقة: شهادات/معايير حقيقية، سعة الإنتاج، أقل كمية للطلب (MOQ)، الدول التي تم التصدير لها (إن وُجدت).
3. الكولكشنات بأسماء واضحة بدل الأكواد.
4. لماذا YKP: مصنع مباشر، تخصيص (OEM/Private Label)، جودة الفوم، الشحن.
5. خطوات التعامل: طلب → عينة → تأكيد → إنتاج → شحن.
6. شهادات عملاء/موزعين (فقط الحقيقية).
7. CTA ختامي + FAQ.

**المنتجات:**
- صفحة كتالوج بفلاتر (الكولكشن، المادة، الاستخدام) وبحث.
- صفحة منتج: معرض صور، مواصفات (الأبعاد، المادة، الوزن، الألوان)، MOQ، التغليف، خيارات التخصيص، زر "اطلب عرض سعر لهذا المنتج" وزر "اطلب عينة".

**نموذج الجملة:**
- نموذج قصير على خطوات (الاسم/الشركة → الدولة → المنتج والكمية → رسالة).
- رسائل تحقق واضحة، حماية من السبام (honeypot/Turnstile)، رسالة نجاح وبريد تأكيد، وتتبع الإرسال في GA4.
- زر واتساب ثابت على الموبايل.

**العام:**
- نظام تصميم موحد (ألوان، خطوط، مسافات، أزرار) في `tailwind.config.js`: الحفاظ على الطابع الفرعوني بشكل راقٍ (ذهبي/داكن) مع تقليل الزخرفة الزائدة والإيموجي في العناوين.
- موبايل أولاً، وأهداف لمس لا تقل عن 44px.
- **نسخة عربية RTL** كاملة (`/ar`) مع `hreflang`.
- إمكانية الوصول (WCAG 2.2 AA): التباين، focus، alt للصور، تنقل بالكيبورد، `aria` للقوائم.
- حذف أو استبدال الشارات والأرقام غير الموثقة.

## 4) المهارات البرمجية المطلوبة من الإيجنت

| المهارة | التفاصيل |
|---|---|
| **Next.js (Pages Router)** | `getStaticProps`/`getStaticPaths`/ISR، `next/image`، `next/head`، `next/font`، middleware، redirects/headers في `next.config.js`، API routes |
| **TypeScript صارم** | أنواع للمنتجات والنماذج، تجنب `any`، `tsc --noEmit` في CI |
| **React** | مكونات قابلة لإعادة الاستخدام، hooks، إدارة حالة بسيطة، تحسين إعادة الرسم |
| **Tailwind CSS** | design tokens، responsive، خصائص RTL/LTR المنطقية (`ms-`, `me-`, `ps-`, `pe-`)، dark mode إن لزم |
| **Technical SEO** | canonical، sitemap، robots، hreflang، JSON-LD، Open Graph، هيكلة العناوين، الروابط الداخلية |
| **Core Web Vitals** | LCP/CLS/INP، تحليل الـ bundle، تحسين الصور والخطوط، تقليل JS |
| **Accessibility** | WCAG 2.2 AA، اختبار بـ axe وlighthouse، التنقل بالكيبورد |
| **UX/CRO لمواقع B2B** | تصميم قمع الطلب، النماذج، دلائل الثقة، صفحات المنتج للجملة |
| **i18n وRTL** | تعدد اللغات في Next.js، `hreflang`، خطوط عربية (مثل Cairo/Tajawal) |
| **Firebase** | Firestore وRemote Config وقواعد الأمان، تجنب كشف المفاتيح الخاصة |
| **النماذج والبريد** | التحقق (zod)، nodemailer، rate limiting، حماية من السبام، معالجة الأخطاء |
| **Vercel** | preview deployments، متغيرات البيئة، redirects، Analytics |
| **Git/GitHub** | فروع لكل مهمة، commits واضحة (Conventional Commits)، PR صغيرة بوصف وقياسات |
| **الاختبار** | Playwright، Lighthouse CI، اختبارات وحدة للدوال المساعدة |
| **الأمان** | سرية الأسرار، رؤوس HTTP، التحقق من المدخلات، مراجعة الاعتماديات (`npm audit`) |
| **تحليلات** | GA4، Search Console، تتبع الأحداث والتحويلات |

## 5) تعليمات للإيجنت (انسخها إلى `AGENTS.md` في جذر المستودع)

```markdown
# AGENTS.md: قواعد العمل على موقع YKP Supplies

## السياق
موقع B2B لتصنيع وتصدير مخدات سفر بتصميمات فرعونية. الهدف الأول: زيادة طلبات الجملة (Wholesale Inquiries) وتحسين ظهور الموقع في البحث.
التقنية: Next.js (Pages Router) + TypeScript + Tailwind + Firebase + Vercel.

## قبل أي تعديل
1. اقرأ الكود المعني وملفات `docs/` أولاً، ولا تفترض.
2. لأي مهمة كبيرة: اكتب خطة قصيرة (ما سيتغير، الملفات، المخاطر) قبل التنفيذ.
3. قِس الوضع الحالي (Lighthouse/ build / tests) لتقارنه بعد التغيير.

## قواعد التنفيذ
- فرع منفصل لكل مهمة، وPR صغير وقابل للمراجعة (يفضل أقل من 400 سطر).
- TypeScript صارم، ولا `any` بدون سبب مكتوب. شغّل `npm run lint` و`npx tsc --noEmit` و`npm run build` قبل أي commit.
- لا تغيّر أي URL موجود بدون redirect 301 في `next.config.js`.
- كل صفحة: title وdescription فريدان، وcanonical، وH1 واحد، وOG image.
- كل صورة عبر `next/image` مع `alt` وأبعاد صريحة، و`priority` لصورة LCP فقط.
- استخدم مكونات وtokens موجودة قبل إنشاء جديدة. لا تضف مكتبة بدون مبرر واضح وقياس لحجمها.
- ادعم RTL بخصائص Tailwind المنطقية، واختبر الصفحات بالعربي والإنجليزي.
- الوصولية: تباين كافٍ، focus واضح، تنقل بالكيبورد، labels للنماذج.

## المحتوى والمصداقية
- ممنوع اختراع شهادات أو أرقام أو آراء عملاء أو تقييمات (لا `aggregateRating` في Schema بدون بيانات حقيقية).
- أي ادعاء (شهادة، عدد دول، سنوات خبرة) يجب أن يكون له مصدر يزوده صاحب الموقع، وإلا اتركه كـ TODO واضح.
- اسم البراند الموحد: **YKP Supplies**؛ لا تستخدم أسماء أخرى في العناوين.

## الأمان
- لا تضع أسراراً في الكود أو الـ commits. استخدم متغيرات البيئة فقط، وحدّث `.env.local.example` بالأسماء بلا قيم.
- كل API route: تحقق من المدخلات (zod)، وrate limiting، ومعالجة أخطاء لا تكشف تفاصيل داخلية.
- نموذج الاتصال: حماية من السبام (honeypot أو Turnstile).

## تعريف الإنجاز (Definition of Done)
- build ناجح، وlint/typecheck/tests بلا أخطاء.
- Lighthouse (موبايل) للصفحات المتأثرة: Performance ≥ 90، SEO ≥ 95، Accessibility ≥ 95، ولا تراجع عن الوضع السابق.
- لا روابط مكسورة، وsitemap محدث.
- وصف الـ PR يتضمن: ما تغير، لماذا، لقطات قبل/بعد، أرقام القياس، وأي أسئلة مفتوحة لصاحب الموقع.

## ممنوع
- إعادة كتابة شاملة بدون موافقة.
- حذف صفحات أو تغيير الدومين الأساسي بدون موافقة.
- الدفع المباشر إلى `master`.
```
